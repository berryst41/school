1깃허브가 뭐예요?

깃허브(GitHub)는 내가 만든 파일을 인터넷에 올려 두는 온라인 보관함이에요. 구글 드라이브와 비슷하지만 두 가지가 특별해요.

  • 📜 고친 기록이 모두 남아요. 언제, 무엇을, 왜 바꿨는지 하나하나 적혀 있어서 예전 모습으로 되돌릴 수도 있어요.
  • 🌐 올린 파일을 웹사이트로 바로 열 수 있어요. 수업용 게임이나 자료 공유 사이트를 만들어 주소 하나로 학생들에게 나눠 줄 수 있어요.

원래는 프로그램을 만드는 사람들이 쓰는 곳이지만, 요즘은 Claude 같은 AI가 코드를 대신 써 주기 때문에 선생님도 충분히 쓸 수 있어요. 내가 할 일은 “무엇을 만들고 싶은지” 말하고, 결과를 확인하는 것뿐이에요.

💡 이렇게 생각하면 쉬워요

깃허브 = 내 작품을 넣어 두는 서랍장. 서랍 하나하나가 “저장소”예요. 서랍마다 안내문(README)이 붙어 있고, 서랍을 열 때마다 언제 무엇을 넣고 뺐는지 기록장이 남아요.

2꼭 알아야 할 낱말

깃허브 화면은 대부분 영어예요. 아래 낱말만 알면 거의 다 읽을 수 있어요. 처음엔 다 외우지 말고, 막힐 때 돌아와서 보세요.

낱말뜻
계정 (Account)깃허브에서 쓰는 내 이름표예요. 아이디가 곧 주소가 돼요. 예) github.com/berryst41
저장소 (Repository, 레포)파일을 모아 두는 서랍 하나예요. 도구 하나, 프로젝트 하나마다 저장소를 하나씩 만들어요.
README (리드미)“나를 먼저 읽어 주세요”라는 뜻의 안내문이에요. 저장소를 열면 파일 목록 아래에 자동으로 보여요. 이름 끝의 .md는 글자를 꾸밀 수 있는 문서라는 표시예요.
공개 / 비공개 (Public / Private)공개는 누구나 볼 수 있고, 비공개는 나와 내가 초대한 사람만 봐요. 웹사이트로 쓰려면 보통 공개로 둬요.
커밋 (Commit)“이렇게 바꿨어요” 하고 저장 도장을 찍는 거예요. 짧은 메모(커밋 메시지)를 함께 남겨요. 초록색 Commit changes 단추가 바로 이거예요.
브랜치 (Branch)원본을 건드리지 않고 따로 고쳐 보는 연습장이에요. 원본 연습장 이름은 보통 main이에요.
PR (Pull Request, 풀 리퀘스트)연습장(브랜치)에서 고친 걸 원본에 넣어도 되는지 묻는 변경 요청서예요. Claude가 고친 내용은 보통 PR로 올라와요.
머지 (Merge, 합치기)PR의 내용을 원본(main)에 실제로 적용하는 거예요. 머지하기 전에는 첫 화면에 바뀐 게 안 보여요.
협업자 (Collaborator)내 저장소를 함께 고칠 수 있게 초대한 사람이에요.
깃허브 페이지 (GitHub Pages)저장소에 올린 파일을 무료 웹사이트로 열어 주는 기능이에요. 주소는 아이디.github.io/저장소이름/ 모양이에요.
깃허브 액션 (GitHub Actions)정해 둔 시간마다 깃허브가 혼자 알아서 하는 일이에요. 예) 매일 아침 사이트 깨우기, 프로필 목록 새로 고치기.
2단계 인증 (2FA)비밀번호에 더해 휴대폰으로 한 번 더 “나 맞아요” 확인하는 안전장치예요.
GitHub Mobile휴대폰용 깃허브 앱이에요. 로그인할 때 “승인” 단추를 누르는 데 쓰여요.
터미널 / PowerShell마우스 대신 글자로 명령을 입력하는 검은(파란) 창이에요. 윈도우에서는 PowerShell이라고 불러요.
CLI터미널에서 쓰는 프로그램이라는 뜻이에요. 예) Claude Code(터미널에서 쓰는 Claude), GitHub CLI(gh, 터미널에서 쓰는 깃허브).

3계정 만들기

  1. github.com/signup에 들어가요.
  2. 이메일, 비밀번호, 아이디(Username)를 적어요.
    • 아이디는 내 사이트 주소에 그대로 들어가요. 예) 아이디가 berryst41이면 사이트는 berryst41.github.io
    • 영어 소문자·숫자로 짧고 기억하기 쉽게 지어요. 학교 이름이나 실명은 넣지 않는 게 좋아요.
  3. 이메일로 온 숫자 코드를 넣으면 가입 끝이에요.
  4. 2단계 인증 켜기: 오른쪽 위 내 사진 → Settings → 왼쪽 Password and authentication → Enable two-factor authentication. 이때 휴대폰에 GitHub Mobile 앱을 깔고 같은 계정으로 로그인해 두면 나중에 편해요.
⚠️ 아이디는 함부로 바꾸지 마세요

아이디를 바꾸면 사이트 주소도 같이 바뀌어요. 예전 주소로 나눠 준 링크와 인쇄해 둔 QR코드는 더 이상 열리지 않아요. 바꿔야 한다면 처음에 바꾸세요.

4첫 저장소 만들기

  1. 깃허브 오른쪽 위 + 단추 → New repository를 눌러요.
  2. Repository name에 이름을 적어요. 예) my-first-repo, school (영어 소문자와 -를 써요)
  3. Public(공개) 또는 Private(비공개)를 골라요. 연습용이면 비공개, 웹사이트로 쓸 거면 공개.
  4. Add a README file을 켜요(On / 체크). 빈 저장소보다 시작하기 훨씬 편해요.
  5. .gitignore, license(라이선스)는 그대로 두고 초록색 Create repository를 누르면 끝!
🎁 특별한 저장소 하나

저장소 이름을 내 아이디와 똑같이 지으면(예: 아이디 berryst41 → 저장소 berryst41) “프로필 꾸미기용” 특별 저장소가 돼요. 거기 README에 쓴 글이 내 깃허브 프로필 첫 화면에 소개글로 보여요. 만들 때 파란 안내문이 뜨는 게 그 뜻이에요.

5파일 올리고 고치기

📤 파일 올리기

  1. 저장소 화면에서 Add file → Upload files를 눌러요.
  2. 컴퓨터에 있는 파일을 화면에 끌어다 놓아요.
  3. 아래 메모 칸에 “첫 파일 올리기”처럼 짧게 적고 Commit changes를 눌러요.

✏️ README(안내문) 고치기

  1. 저장소 첫 화면 아래 README 상자의 오른쪽 위 연필 아이콘 ✏️을 눌러요.
  2. “깃허브 연습 중입니다.” 같은 한 줄을 적어요.
  3. 오른쪽 위 Commit changes를 누르고, 뜨는 창에서 한 번 더 눌러요. (두 번 눌러야 저장돼요)
💡 README에는 무엇을 쓰나요?

“이 저장소가 무엇이고, 어떻게 쓰는지”를 적어요. 책의 머리말, 폴더에 붙이는 표지라고 생각하면 돼요. 내가 만든 사이트 주소들을 모아 적어 두는 곳으로 써도 좋아요.

⚠️ 공개 저장소에는 개인정보를 올리지 마세요

학생 이름, 사진, 전화번호, 비밀번호 같은 건 공개 저장소에 올리면 누구나 볼 수 있어요. 한 번 올라간 건 기록에 남으니 처음부터 조심해요.

6웹사이트로 공개하기 (GitHub Pages)

저장소에 index.html 파일이 있으면, 그 파일을 웹사이트로 열 수 있어요. 수업용 게임이나 자료 공유 사이트를 이렇게 올려요.

  1. 저장소 위쪽 Settings → 왼쪽 Pages를 눌러요.
  2. Source는 Deploy from a branch, Branch는 main 과 / (root)를 고르고 Save.
  3. 1~2분 기다린 뒤 새로고침하면 위쪽에 “Your site is live at …”과 주소가 나와요.

주소 모양: https://아이디.github.io/저장소이름/
폴더 안의 파일은 주소 뒤에 폴더 이름을 붙여요. 예) …/school/share/, …/school/docs/claude-guide.pdf

💡 고쳤는데 사이트가 그대로예요

사이트에 반영되기까지 1~2분 걸려요. 기다린 뒤 Ctrl + F5로 새로고침해 보세요.

⚠️ 무료 저장 서비스는 안 쓰면 잠들어요

학생들이 올린 파일처럼 데이터를 저장하는 사이트는 Supabase 같은 바깥 서비스를 함께 써요. 무료 요금제는 일주일쯤 아무도 안 쓰면 일시 정지되고 “곧 멈춘다”는 메일이 와요. 데이터가 지워지는 건 아니고 대시보드의 Restore로 다시 켤 수 있어요. 깃허브 액션으로 매일 한 번 자동으로 깨워 두면 걱정 없어요(Claude에게 “사이트가 안 잠들게 해 줘”라고 하면 돼요).

7저장소·프로필 꾸미기

📘 저장소 첫 화면(README) 꾸미기

README에는 표, 굵은 글씨, 그림, 눌러서 펼치는 칸까지 넣을 수 있어요. 직접 쓰기 어려우면 Claude에게 이렇게 말해 보세요.

school 저장소 첫 화면을 한눈에 보기 좋게 꾸며 줘. 맨 위에 도구 목록 표를 넣고, 자세한 설명은 눌러서 펼치게 해 줘.
  • 저장소 맨 위 파일 목록과 그 옆의 회색 글씨(커밋 메시지)는 깃허브가 모든 저장소에 똑같이 보여 주는 화면이라 숨길 수 없어요. 보는 사람은 대부분 그 아래 README를 봐요.
  • 저장소 오른쪽 About 옆 ⚙️ → Description에 한 줄 소개를 적으면 목록에서 보기 좋아요.

🙋 프로필 꾸미기

  1. 아이디와 같은 이름의 저장소(4번의 특별 저장소)를 만들고 README에 소개를 적어요.
  2. 내 사진 → Your profile → Edit profile에서 사진, 이름, 한 줄 소개(Bio)를 바꿔요. (이건 본인만 할 수 있어요)
  3. 프로필의 Customize your pins를 누르고 자랑하고 싶은 저장소에 체크 → Save pins. 프로필에 카드로 크게 보여요. (이것도 본인만 할 수 있어요)

8다른 사람과 나누기

이럴 때이렇게 해요
👀 구경만 하게저장소 주소(github.com/아이디/저장소)나 프로필 주소를 카톡·메일로 보내요. 공개 저장소는 계정이 없어도 볼 수 있어요.
🎮 도구만 쓰게사이트 주소(아이디.github.io/저장소/)를 보내요. 가장 간단해요.
🤝 같이 고치게저장소 → Settings → Collaborators → Add people → 상대 아이디나 이메일 입력. 상대가 메일로 온 초대를 수락해야 끝나요. 코드를 고칠 수 있게 되니 믿을 수 있는 사람만 초대해요.
💡 계정이 두 개일 때

계정을 바꾸지 않아도 돼요. 쓰는 계정을 다른 계정 저장소의 협업자로 초대하고 수락하면 두 저장소를 모두 쓸 수 있어요. 다만 초대는 저장소마다 따로 해야 해요.

9Claude와 함께 쓰기

Claude에게 깃허브를 연결해 두면 “이런 게 필요해” 한마디로 Claude가 파일을 만들고 고쳐서 저장소에 올려 줘요.

🔗 연결하기

  1. claude.ai에 로그인한 상태에서 claude.ai/connect-github에 들어가요.
  2. 깃허브 로그인 창이 뜨면 Claude가 써도 되는 계정으로 로그인해요.
  3. “Claude 앱을 어느 저장소에 설치할까요?” 하고 물으면 All repositories(모든 저장소) 또는 쓸 저장소만 골라 Install.

🔁 Claude가 고친 걸 적용하는 흐름

  1. Claude가 연습장(브랜치)에서 고치고 PR(변경 요청서)을 올려요.
  2. PR 링크를 열어 Files changed 탭에서 바뀐 내용을 볼 수 있어요.
  3. 괜찮으면 아래쪽 Merge pull request → Confirm merge. 이제 원본에 적용돼요.
💡 매번 누르기 귀찮다면

Claude에게 “앞으로 고친 건 묻지 말고 알아서 적용(머지)해 줘”라고 말해 두세요. 프로젝트를 쓰고 있다면 프로젝트 지침에 적어 두면 새 대화에서도 그대로 지켜요.

⚠️ Claude도 못 하는 일 (본인만 할 수 있어요)

저장소 삭제, 프로필 저장소 고정(pins), 프로필 사진·Bio 바꾸기, 2단계 인증 승인. 이런 건 깃허브가 일부러 본인만 할 수 있게 막아 뒀어요.

“main 브랜치를 보호하세요(Protect your main branch)” 안내가 떠요

여러 사람이 함께 쓸 때 원본을 실수로 덮어쓰지 못하게 막는 기능이에요. 혼자 쓰고, Claude가 PR로 올리는 방식이라면 꼭 필요하지 않아요. Dismiss(닫기)를 눌러도 괜찮아요. 괜히 켜면 적용할 때 막히는 일이 생길 수 있어요.

10내 컴퓨터에 도구 설치하기

여기부터는 선택이에요. 웹 화면에서 Claude로만 써도 충분해요. 내 컴퓨터의 파일을 Claude가 직접 다루게 하거나, 프로그램을 내 컴퓨터에서 실행해야 할 때 설치해요.

🥇 가장 쉬운 길: Claude 데스크톱 앱

  1. claude.ai/download에서 Claude 앱을 받아 설치해요.
  2. 시작 메뉴의 주황색 Claude 아이콘을 열고 로그인해요.
  3. 위쪽(또는 왼쪽 위)의 Chat · Cowork · Code 중 Code를 누르고, 작업할 폴더를 골라요.
ChatCode
대화만 해요. 결과를 글로 보여 주고, 파일은 내가 직접 복사해서 써요.내 컴퓨터 폴더 안에서 직접 일해요. 파일을 만들고 고치고 실행해서 확인까지 해 줘요.

⌨️ 터미널에서 쓰는 Claude Code

PowerShell 여는 법: 시작 단추를 누르고 “PowerShell”이라고 친 뒤 Windows PowerShell을 눌러요. 아래 줄을 복사해 붙여 넣고(마우스 오른쪽 클릭 또는 Ctrl+V) Enter를 눌러요.

irm https://claude.ai/install.ps1 | iex

맥이라면 터미널에서 이 줄을 넣어요.

curl -fsSL https://claude.ai/install.sh | bash
  1. 1~2분 동안 아무 표시가 없을 수 있어요. 끝나면 PS C:\...> 줄이 다시 나와요.
  2. 설치가 끝나면 PowerShell 창을 닫고 새로 열어요. (새 창에서만 claude를 알아들어요)
  3. 작업용 폴더를 따로 만들어요. 내 사용자 폴더 전체를 맡기는 것보다 안전해요.
    mkdir claude-work; cd claude-work claude
  4. 처음 한 번은 이렇게 물어요.
    • 화면 색 고르기 → 그대로 Enter
    • 로그인 방법 → Claude account를 고르고, 열리는 브라우저에서 로그인
    • 안전 안내(Claude도 실수할 수 있어요) → Enter
    • “이 폴더를 믿나요?” → 작업용 폴더라면 Yes, I trust this folder. 사용자 폴더 전체(C:\Users\…)를 묻는다면 No, exit로 나가서 위의 작업용 폴더로 다시 시작해요.
  5. 맨 아래 > 옆에 한국어로 하고 싶은 일을 적고 Enter. 끝낼 때는 /exit를 입력하거나 창을 닫아요.

다음부터는 PowerShell을 열고 이렇게만 치면 돼요.

cd claude-work claude
💡 Git이 없다고 나오면

Git for Windows를 먼저 설치해요. 설치 창은 모두 기본값 그대로 Next만 눌러도 돼요.

🐙 GitHub CLI(gh) 설치하고 로그인하기

터미널에서 깃허브를 쓰게 해 주는 도구예요. Claude Code가 내 컴퓨터에서 깃허브에 올리거나 PR을 만들 때 필요해요.

winget install --id GitHub.cli --source winget
  1. 다 받고 설치 창이 뜨면 예를 눌러요. Successfully installed가 나오면 성공.
  2. PowerShell을 닫고 새로 연 뒤 로그인해요.
    gh auth login
  3. 질문이 차례로 나오면 화살표 키로 고르고 Enter.
    물어보는 것고를 것
    Where do you use GitHub?GitHub.com
    preferred protocol (연결 방식)HTTPS
    Authenticate Git with your GitHub credentials?Yes (Y)
    How would you like to authenticate?Login with a web browser
  4. 화면에 XXXX-XXXX 같은 한 번만 쓰는 코드가 나와요. Enter를 누르면 브라우저가 열리니, 그 코드를 넣고 Authorize를 눌러요.
  5. 휴대폰 GitHub Mobile로 확인을 하라고 하면, 앱에 뜬 숫자 중 컴퓨터 화면에 나온 숫자(예: 75)를 누르고 승인해요. 그러면 컴퓨터 화면이 저절로 넘어가요.
  6. PowerShell에 Logged in as 아이디가 나오면 끝!
📱 GitHub Mobile 알림이 안 와요
  1. 알림을 기다리지 말고 휴대폰에서 GitHub 앱을 직접 열어 보세요. 앱 안에 확인 요청이 떠 있는 경우가 많아요.
  2. 없으면 앱 화면을 아래로 당겨 새로고침하고, 앱이 같은 계정으로 로그인돼 있는지 확인해요.
  3. 그래도 안 되면 컴퓨터 화면 아래쪽의 다른 확인 방법(인증 앱 코드, 비밀번호, 이메일 등)을 눌러서 확인해요.

11학교 컴퓨터에서 막힐 때

학교 인터넷은 보안 장비가 중간에서 연결을 검사하기 때문에, 집에서는 잘 되는 설치가 학교에서만 막히는 일이 많아요. 아래 순서대로 해 보세요.

이런 화면이 나와요이렇게 해 보세요
설치 줄을 넣고 몇 분째 아무 반응이 없어요① Enter를 눌렀는지 확인 → ② 5분 기다리기 → ③ 그래도 그대로면 창을 닫고 새로 열어 한 번 더. 계속 안 되면 학교망이 막고 있는 거예요. 아래 winget이나 핫스팟 방법으로 가요.
내려받다가 연결이 끊겼다는 빨간 글씨같은 줄을 한 번 더 실행해요. 또 끊기면 아래 방법으로 가요.
winget으로 설치하다 msstore(마이크로소프트 스토어) 오류스토어 쪽만 막힌 거예요. 줄 끝에 --source winget을 붙여 어디서 받을지 정해 줘요.
winget install Anthropic.ClaudeCode --source winget
“인증서가 맞지 않습니다”(certificate) 오류학교망 보안 장비 때문에 자주 나요. 휴대폰 핫스팟에 연결한 뒤 처음 설치 줄(irm https://claude.ai/install.ps1 | iex)을 다시 실행하는 게 가장 확실해요. 설치만 핫스팟으로 하면 그다음부터는 학교망에서 써도 돼요.
설치는 됐는데 claude를 치면 “인식되지 않습니다”PowerShell 창을 닫고 새로 열어서 다시 쳐요. 설치 직후에는 새 창에서만 알아들어요. (gh도 똑같아요)
앱 다운로드 자체가 안 돼요학교 정보 담당 선생님께 claude.ai, github.com 접속 허용을 부탁드려요.
💡 휴대폰 핫스팟 켜는 법

휴대폰 설정 → 연결(또는 네트워크) → 모바일 핫스팟을 켜요. 컴퓨터 오른쪽 아래 와이파이 아이콘에서 휴대폰 이름을 골라 연결해요. 설치가 끝나면 다시 학교 와이파이(또는 유선)로 돌아와도 돼요.

💡 막혔을 때 Claude에게 물어보는 법

PowerShell 창을 캡처(윈도우키+Shift+S)해서 보여 주거나, 빨간 글씨를 그대로 복사해 붙여 넣고 “이거 뭐야?”라고 물어보세요. 캡처 첨부가 실패하면 글자만 붙여 넣어도 돼요.

12자주 묻는 질문

Claude가 고쳤다는데 저장소 화면이 그대로예요

아직 PR이 머지(적용)되기 전이라 그래요. PR 링크에서 Merge pull request를 누르거나 Claude에게 “적용해 줘”라고 하세요. 머지했는데도 그대로면 F5로 새로고침해요.

저장소를 지우고 싶어요

지울 저장소 → Settings → 맨 아래 빨간 Danger Zone → Delete this repository → 확인 단추를 몇 번 누르고, 마지막에 아이디/저장소이름을 그대로 따라 적으면 지워져요.

⚠️ 되돌릴 수 없어요. 그 저장소로 열던 사이트도 함께 사라져요. 지우기 전에 남길 파일이 없는지 꼭 확인해요. (Claude는 대신 지워 줄 수 없어요)

“워크플로가 실패했어요(Run failed)” 메일이 왔어요

깃허브 액션(정해진 시간마다 저절로 도는 일)이 한 번 실패했다는 알림이에요. 메일 내용을 Claude에게 보여 주면 원인을 찾아 고쳐 줘요. 이미 고쳐진 뒤라면 무시해도 돼요.

깃허브 액션을 쓰면 돈이나 Claude 사용량이 드나요?

공개 저장소의 깃허브 액션은 무료예요. 한 번 설치한 뒤에는 깃허브가 혼자 돌리기 때문에 Claude 사용량(토큰)도 거의 들지 않아요.

다른 저장소에 새로 올린 게 프로필에 자동으로 나오나요?

기본으로는 안 나와요. 프로필 README도 그냥 글이 적힌 파일이라서요. 깃허브 액션으로 “한 시간마다 내 저장소 목록을 읽어 프로필 표를 새로 쓰기”를 달아 두면 자동으로 바뀌어요. Claude에게 부탁하면 설치해 줘요.

“차단됨”, “업로드 실패” 같은 표시가 떠요 (Claude 프로젝트)

“차단됨”은 고장이 아니라 Claude가 내 답을 기다리는 중이라는 뜻이에요. 그 대화에 한 줄 답을 남기면 바뀌어요. 사진 첨부가 실패하면 새로고침한 뒤 다시 올리거나, 글로 적어 보내요.

남들은 깃허브를 어떻게 꾸며요?
  • 예쁜 프로필 모음
  • 교육 관련 저장소 모음
  • 요즘 인기 있는 저장소

마음에 드는 걸 찾으면 링크를 Claude에게 주고 “이런 느낌으로 꾸며 줘”라고 하면 돼요.
